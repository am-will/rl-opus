# Champions Field (Opus build)

A from-scratch recreation of Rocket League's **Champions Field** arena for Blender 5.2 / EEVEE.

Entirely procedural — no external assets. Every mesh, texture and material is
generated by this package, so the whole arena rebuilds deterministically in
about 15 seconds.

```bash
blender -b --factory-startup --python tools/champions_field_opus/build.py -- \
    --samples 64 --res 1920 1080 --shots hero,goal,broadcast --tag v1_
```

Useful flags: `--greybox` (shell only), `--quick-tex` (low-res maps, fast
iteration), `--no-crowd`, `--no-render`, `--haze`, `--out`, `--renders`.

Outputs `assets/ChampionsFieldOpus/champions_field.blend` plus its texture maps
in `assets/ChampionsFieldOpus/tex/`, and stills to `renders/champions_field_opus/`.

## Dimensional accuracy

Play-volume geometry is built from the published RLBot values, not eyeballed —
see `cf/const.py`, where every number is in Unreal units (1 uu = 1 cm) so it can
be diffed against the reference table directly.

| | value |
|---|---|
| Play area | 8192 × 10240 uu, ceiling 2044 |
| Side / back walls | x = ±4096, y = ±5120 |
| Corner planes | 45°, on \|x\| + \|y\| = 8064 |
| Goal mouth | 1785.51 wide × 642.775 tall, 880 deep |
| Centre circle | 3686.4 uu diameter |
| Boost pads | all 34, exact coordinates, 6 big / 28 small |
| Ball | r = 91.25, resting z = 93.15 |

Values that Psyonix has never published (corner fillet radius, wall-panel band
heights, stand rake) are marked `ART` in `const.py` and were matched by eye
against reference stills.

## Collision

The pitch is **one flat surface**: `CF_Floor` is a single planar n-gon at z = 0
that runs straight through both goal mouths, so there is no seam or step
anywhere a car can drive.

`build.py` tags every mesh with a `collision` custom property and links the
colliding ones into a `Collision` collection, so an exporter has a one-click
selection:

| collision | meshes |
|---|---|
| yes | `CF_Floor`, `CF_Walls`, `CF_Ceiling`, `CF_GoalPockets` |
| no | everything else — boost decals and beams, goal frames, nets, ball, crowd, stands, roof, jumbotron, signage |

Boost pads carry no thickness at all. The pad is a single flat polygon 1.5 cm
proud of the deck, and the only thing that rises off it is alpha-blended
emission with no shadow casting — light, not matter. `verify.py` asserts this
(`BoostDecal max height`, `beam casts no shadow`, `pads/props non-collision`),
so nobody can quietly reintroduce a lip.

## How it's put together

The arena shell is **one swept surface**, not a boolean. A plan-view boundary —
an octagon with its eight joins filleted — is swept along a vertical
cross-section (floor fillet → vertical run → ceiling fillet). Two properties
fall out of this that a boolean approach doesn't give you:

- Offsetting the boundary inward by *d* just shrinks each corner arc to
  `R − d` about a fixed centre, so the floor, ceiling and every stand tier are
  exactly concentric with the wall for free.
- The sampler is told to plant vertices exactly on the goal posts, so the goal
  mouths land on real edges instead of a boolean seam.

The same `ring(inset)` function drives the pitch, the seating bowl (at negative
inset), the LED ribbons, the roof truss and the floodlight ring.

Textures are drawn with a small **signed-distance canvas** (`cf/canvas.py`) —
including a stroke font, since Blender ships no PIL. Markings are therefore
placed at true world coordinates and antialiased analytically rather than
supersampled.

| module | role |
|---|---|
| `const.py` | dimensions, palette, boost table |
| `arena.py` | swept shell, goal pockets, plan-curve maths |
| `canvas.py` | SDF drawing canvas + stroke font + value noise |
| `textures.py` | turf, wall, hex-net and hero-board maps |
| `materials.py` | pitch / wall / canopy shaders |
| `props.py` | goal frames, nets, boost pads, ball |
| `stands.py` | raked tiers, ~25k spectators, roof |
| `structure.py` | jumbotron, truss, ribbons, bunting, trophy |
| `lighting.py` | 18 floodlight banks, team wash, fills |
| `world.py` | night sky, stars, cloud, haze |
| `shots.py` | cameras, EEVEE config, glare |

## Notes / gotchas hit along the way

Blender 5.2 specifics worth knowing if you extend this:

- The scene compositor is a **node group** (`scene.compositing_node_group`), and
  it must be fed by a `CompositorNodeRLayers` *inside* the group — a Group Input
  socket renders empty. `CompositorNodeComposite` no longer exists.
- The Glare node is configured through **input sockets**, and its menu sockets
  take display names (`"Bloom"`, `"Streaks"`, `"High"`), not enum identifiers.
- The wall is viewed from inside the bowl, so its U must run *against* the
  ring's winding. The texture generator's world lookup has to be reversed to
  match, or team colours land on the mirrored half.
- `shadow_pool_size` caps at 2048 MB; with 18+ lights, turn shadows off on the
  fill lights rather than raising it.
- A spot light placed at its own fixture's centre is fully self-occluded and
  contributes nothing — offset the emitter clear of the housing.
